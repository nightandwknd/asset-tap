# Browser viewer feasibility spike: harness and handoff

An isolated, throwaway harness that asks one question: can the existing 3D
viewer and the humanoid rig run in a browser via `wasm32`? Findings are in
[FEASIBILITY.md](FEASIBILITY.md). This file is how to build, serve and verify.

**Status: verified in Chrome 153 (macOS, Apple M3 Pro, WebGL 2.0).** All three
fixtures load, render a textured mannequin and play the baked walk; pause/play,
orbit, zoom and reset work. The first run rendered a blank canvas (WebGL2 rejects
a blit into eframe's multisampled default framebuffer); `start()` now creates the
context with `antialias: false` first. Details and numbers are in
[FEASIBILITY.md](FEASIBILITY.md). Not yet checked: Firefox, Safari, other GPUs.

This directory is its own Cargo workspace with its own `Cargo.lock`. It is not a
member of the repository workspace, so it cannot affect desktop builds, CI or the
root lockfile.

## Layout

| Path                      | What it is                                                                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `shim-core/`              | `#[path]`-includes the **real, unmodified** `core/src/rig/` tree. Small stand-in modules replace the few seams to the rest of core (settings, bundle helpers, constants, network fetch). Library name is `asset_tap_core` so unmodified GUI code resolves. |
| `web/`                    | Browser harness. Compiles the **real** `gui/src/viewer/model.rs` (see FEASIBILITY.md for the exact, asserted patch set), plus a new bytes loader and a minimal eframe-web shell.                                                                  |
| `wasm-probe/`             | DOM-free `wasm32-unknown-unknown` probe, run under Node, for rayon/path-API/skinning checks on the browser target.                                                                                                                               |
| `native-probe/`           | Times bind, bake and skinning over the real rig source. Builds natively and for `wasm32-wasip1`.                                                                                                                                                 |
| `tools/gen_fixture.py`    | Generates the synthetic mannequin GLB (stdlib only).                                                                                                                                                                                             |
| `tools/make-fixtures.sh`  | Regenerates all fixtures end to end.                                                                                                                                                                                                             |
| `tools/build-web.sh`      | Builds the wasm bundle into `web/www/pkg/`.                                                                                                                                                                                                      |
| `tools/serve.sh`          | Static server on `127.0.0.1` only.                                                                                                                                                                                                               |
| `tools/run_wasi.mjs`, `tools/run_wasm_probe.cjs` | Node drivers for the two probes.                                                                                                                                                                                                  |
| `results/`                | Raw output of every measurement quoted in FEASIBILITY.md.                                                                                                                                                                                        |
| `web/www/fixtures/`       | `mannequin_g4.glb` (unrigged input) and `mannequin_g4_baked.glb` (committed). Larger `_g20_`/`_g55_` baked files are git-ignored; regenerate them with `tools/make-fixtures.sh`.                                                                 |

## Fixtures and licensing

- The mannequin geometry and texture are generated by `tools/gen_fixture.py`
  from boxes and a procedural pattern. No third-party art.
- The baked animation (`Walk_Loop`) comes from the repo's `packs/ual1`, which is
  CC0 (see `packs/NOTICE`).
- The repo's large showcase model was **not** used.

## Prerequisites

- Rust **1.97.x** (the repo's pinned toolchain) with the
  `wasm32-unknown-unknown` target.
- `wasm-bindgen-cli` at exactly the version in `Cargo.lock`
  (`tools/build-web.sh` prints it; it was `0.2.130` when this was written):
  `cargo install wasm-bindgen-cli --version 0.2.130 --locked`
- Python 3 (static server and fixture generator). Node 20+ only for the probes.
- A browser with **WebGL2** for the harness itself.

No system OpenSSL or `make` is needed: nothing in this directory builds
`reqwest`.

## Build and serve

```bash
cd spike/browser-viewer
tools/build-web.sh        # release build + wasm-bindgen -> web/www/pkg/
tools/serve.sh            # http://127.0.0.1:8137/  (PORT=... to change)
```

Open: <http://127.0.0.1:8137/?glb=fixtures/mannequin_g4_baked.glb>

Optional larger fixtures (regenerate if the files are missing):

```bash
tools/make-fixtures.sh
# then ?glb=fixtures/mannequin_g20_baked.glb   (42k verts, 77k tris, 3.4 MB)
#      ?glb=fixtures/mannequin_g55_baked.glb   (301k verts, 581k tris, 24 MB)
```

You can also drag any `.glb` onto the canvas (bytes arrive via the browser, not
a path).

## Browser verification checklist

The page publishes machine-readable state as JSON in `window.__viewerStatus` and
mirrors it in the box under the canvas. Check, in order:

1. **Page loads.** No red "init failed" / "window error" text. If it says
   `WebGL2 is not available`, stop and record the browser/profile.
2. **GL context.** `gl` contains `WebGL 2.0` plus a renderer string. Record it.
3. **Model loaded.** `loaded: true`, `error: null`, and for the default fixture
   `verts: 2400`, `tris: 3072`, `hasClip: true`, `clipSeconds` about `1.333`.
4. **Rayon on the browser target.** `rayonProbe` reads
   `par_iter ok ... current_num_threads=1` (Node showed this; confirm in a browser).
5. **It renders.** A blocky T-pose mannequin with a four-colour checker texture
   and a visible metallic sheen (base-colour texture, metallic 0.6, roughness
   0.4). A blank or black canvas with `loaded: true` is a **render failure**:
   capture the browser console.
6. **Baked animation plays.** `playing: true`, `playTime` advances between two
   reads and wraps at about `1.333`; the figure visibly walks. **Pause** freezes
   `playTime` and the pose; **Play** resumes.
7. **Interaction.** Drag orbits, wheel zooms, **Reset camera** returns.
8. **Larger fixtures.** Repeat 3, 5 and 6 with `_g20_` and `_g55_`. Record
   `parseMs`, `gpuUploadMs`, the observed frame rate (browser performance panel)
   and tab memory. These are the numbers this spike could not obtain.

Record with each result: browser name and version, OS, GPU/driver, and the
`gl` string.

### Known issues and remaining risks

- **Framebuffer blit (hit, fixed).** `render_direct` blits an offscreen target
  into egui's framebuffer. eframe's bare `getContext("webgl2")` is antialiased,
  so the blit raised `INVALID_OPERATION` every frame and the canvas stayed blank
  while the status read `loaded: true`. Fixed in `web/src/lib.rs`. A real
  extraction must make the web host create a non-MSAA context.
- **Float render targets (not hit on Chrome/ANGLE Metal).** The
  image-based-lighting passes can need `EXT_color_buffer_float`; other
  browsers or GPUs may differ.
- **Colour/gamma.** The model reads darker and more muted than the "metallic
  sheen" described above; not compared against desktop.
